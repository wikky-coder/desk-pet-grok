# 桌宠 grok 下一版功能设计（v-next）

日期：2026-10-11　状态：草案，待 Wiki 确认优先级
范围：在现有 2.5D 立绘 + 部件骨骼桌宠上做增量，不换画风、不改形象，不引入新的系统权限（除非条目里明说）。

---

## 0. 结论先行

1. 现有产品已经是「会动、会聊、能趴窗口、能看屏幕、能摸头」的桌宠，**表现层（动作/表情/物理小动作）在开源桌宠里属于上游**，短板在**陪伴深度**（没有跨会话记忆、不会主动找人、没有语音）和**可靠性/可维护性**（实验开关多、部分功能靠真机才能验证、窗口层代码集中在一个大文件）。
2. 对比 N.E.K.O：她是「AI 伴侣平台」，我们是「有手感的桌宠」。不要追平台能力（插件商城、Agent 操控电脑、多端），那是 10 倍工作量且与「轻、省额度、不抢焦点」的定位冲突。**该追的只有三样：跨会话记忆、主动开口、语音**，其余保持自己的优势（手感、骨骼动画、低成本）。
3. 建议下一版主线：**P0 稳定性与可验证性 → P1 记忆与主动陪伴 → P2 表情/动作扩展 → P3 语音与分发**。每项带验收标准，见第 4 节。

## 1. 现状盘点

### 1.1 功能（截至本次提交）

| 模块 | 现状 | 成熟度 |
| --- | --- | --- |
| 形象/动画 | 2.5D：预渲染待机/转身/行走片 + 部件骨骼（耳、呆毛、侧发、四节尾巴、头、裙摆弹簧），呼吸、耳抖、拖拽倾斜、跳跃 | 高；转身/行走仍有预渲染片的「换视图」痕迹 |
| 运动 | 散步（惯性/转向/停顿）、原地；眼睛看向鼠标（本版改成只动眼睛的被动默认行为） | 中高 |
| 趴窗口/输入框 | 拖到窗口顶边趴下、呼吸、哈欠、睡着；可用辅助功能精确到输入框；自己走过去；**本版新增：边缘下移时掉落，落到新边缘重新趴或落地缓冲站起** | 中；依赖真机验证 |
| 摸头 | **本版新增**：鼠标在头顶来回摆动判定，眯眼、耳朵压低、尾巴摇、下沉，台词限频 | 中；灵敏度待真机调 |
| 聊天 | xAI Responses API 流式；猫娘人设（本喵/主人/Wiki，句尾喵）；奶白圆角聊天框、猫爪发送键 | 中高 |
| 屏幕感知 | 第一档读前台软件名/窗口标题（免费）；第二档限频截图 + 视觉模型（默认 3 次/小时、20 次/天，黑名单、安静时段、标记） | 中 |
| 系统 | 托盘、右键菜单、开机自启、双击启动 App、天气、CPU/内存提醒、API Key 管理 | 高 |
| 工程 | 约 8.7k 行 Python（`desk_pet_grok/`）、42 个测试文件、本版后约 375 个用例；设计书、各轮离屏渲染图 | 中高 |

### 1.2 手感（主观评估，需 Wiki 真机确认）

- 优点：待机呼吸 + 耳抖 + 裙摆弹簧让她「不死板」；趴姿和摸头都有专门素材/骨骼反应；眼睛跟随不转头，不会再有「突然转身」。
- 缺点：
  - 行走/转身仍是预渲染片，和骨骼待机之间靠 0.16 秒渐变过渡，高速切换时偶有可见的「两个姿势叠一下」。
  - 眼睛跟随与摸头眯眼是在最终画面上做的局部处理（无独立瞳孔层），幅度只有约 ±2 屏幕像素（默认 220 高度），**是「有」但不「抢眼」**；若想更明显需要补瞳孔分层素材。
  - 受惊表情只有「眼睛放大 + 耳朵尾巴上飘」，没有专门的惊讶嘴型。
  - 趴姿是正面探头，不是完整侧身趴卧。

### 1.3 稳定性与已知缺陷

| # | 缺陷/风险 | 影响 | 现状 |
| --- | --- | --- | --- |
| D1 | 部件骨骼、转身、趴窗口仍是「实验开关」，默认配置与完整体验不一致；本版摸头/掉落会按需自动加载骨骼，但行走/转身骨骼仍需手动开 | 新用户看不到最佳效果 | 已知 |
| D2 | 趴窗口依赖「窗口几何轮询」（0.5 秒一次）与辅助功能权限；多显示器、全屏 App、Stage Manager 下行为未系统测过 | 位置偏差、掉落误判 | 未验证 |
| D3 | 掉落判定「窗口上边下移 > 48px 且快于 70px/s」，这个阈值是估的，真实拖动窗口/最大化/切换空间的数据没采过 | 误触发（掉了不该掉）或漏触发 | 未验证 |

| D7 | 眼睛叠加处理按 360×470 画布硬编码眼位；换立绘/换版本会错位 | 换形象即失效 | 已知 |

| D10 | 掉落/趴窗口/摸头的最终手感只能在真机看；离屏渲染只验证了关键帧 | 验收需要人工 | 已知 |

### 1.4 额度成本

- 聊天：按对话次数计费，单次很小；无后台自动调用。
- 屏幕视觉：缩图 JPEG + 限频（3/小时、20/天），粗估每天最多 20 次小图调用，**数量级低于日常聊天**；有本地用量计数。没有真实账单数据，**需上线后观察一周再定上限**。
- 摸头、眼睛跟随、掉落：纯本地，**零额度**。
- 本版新增的记忆/主动开口若接模型，必须延续「本地先判断、再限频」的原则（见 P1）。

### 1.5 维护性

- 优点：纯逻辑模块 Qt-free 且有测试（运动、趴窗口状态机、摸头检测、掉落物理、台词）；渲染和状态机分层；每轮有离屏渲染产物。
- 缺点：窗口层大文件（D5）；Mac 专用能力（辅助功能、窗口层级）无法在 CI 里测；无 CI；无发布流程（手动传文件）。

## 2. 对比 N.E.K.O 等开源桌宠

| 维度 | 本产品 | N.E.K.O（Apache-2.0，Steam 抢先体验 2026-01） | 其他典型开源桌宠（Shimeji 系、Live2D 桌宠、DyberPet 等） |
| --- | --- | --- | --- |
| 形象 | 单一手绘 2.5D 角色 + 部件骨骼，风格统一 | Live2D / VRM / MMD / PNGTuber / 猫咪桌宠多种形态，可换模型，创意工坊 | Shimeji 靠帧动画 + 行为脚本；Live2D 桌宠靠模型 |
| 动作手感 | 弹簧次级动画、趴窗口、摸头、掉落、眼睛跟随 | 依赖模型自带动作与动作捕捉，全屏追踪 | Shimeji 的「爬窗口边、掉落、被拖拽」行为很成熟，但无 AI |
| 对话 | xAI 流式，猫娘人设 | 实时语音 + 文字，14–20+ 服务商，免费模型开箱即用 | 多数无或简单 |
| 记忆 | **无跨会话记忆** | 五类持久记忆（工作/近期/事实/反思/人格） | 无 |
| 主动陪伴 | 定时台词 + 前台软件名/截图偶发评论 | 屏幕理解、热搜、媒体分享，主动发起话题 | 无或定时提醒 |
| 屏幕理解 | 软件名/标题 + 限频截图 | 实时视觉理解、共享屏幕 | 无 |
| 工具/Agent | 无（刻意） | 操作浏览器和电脑、插件、CUA | 无 |
| 生态 | 无 | 插件商城、创意工坊、多端 | 社区皮肤包 |
| 成本/隐私 | 默认全本地动画，API 仅聊天与限频视觉 | 本地优先，但功能面大，权限面大 | 几乎为零 |
| 体量 | 约 9k 行，单人可维护 | 平台级，多服务（Web/记忆服务/插件） | 小 |

**取舍判断**
- 追：**记忆、主动开口（带限频）、语音**。这三项对「陪伴感」提升最大，且能在不引入 Agent/插件的前提下做。
- 学：Shimeji 系的「窗口交互」行为库（本版已补掉落，后续可补：被窗口边缘夹住、爬窗口侧边——但与 2.5D 正面素材冲突，不建议）。
- 不追：多模型/多形态、插件商城、Agent 操控电脑、多端同步。理由：与「轻量、不抢焦点、额度可控、单人维护」的定位冲突，投入产出比低。

## 3. 路线与优先级

优先级定义：P0 = 不做会影响现有体验的可靠性；P1 = 最大体验提升；P2 = 锦上添花；P3 = 后续。
工作量单位：人天（有 AI 协助的单人、含测试与真机验证），为粗估，±50%。

| ID | 功能 | 优先级 | 工作量 | 额度影响 | 主要风险 |
| --- | --- | --- | --- | --- | --- |
| F1 | 真机验证与阈值校准（摸头/掉落/趴窗口） | P0 | 1.5 | 无 | 需要 Wiki 配合试用 |

## 4. 各项设计与验收标准

### F1 真机验证与阈值校准（P0，1.5 天）

**内容**
1. 加一个隐藏的「调试记录」开关：把摸头判定输入（折返数/幅度/速度，不记录屏幕坐标以外的信息）和掉落判定输入（边缘位移、速度）写到本地日志，供校准。默认关。
2. Wiki 用 3 天；根据日志调 `petting.PARAMS`（低/中/高）与 `lounge.FALL_GAP / FALL_FOLLOW`。
3. 补一份「真机检查清单」（见本文附录 A）。

**验收标准**
- 摸头：中档下，正常用鼠标/触控板在头顶来回蹭 5 次，至少 4 次触发；正常把鼠标移过她头顶（单向）20 次，误触发 ≤1 次。
- 掉落：把窗口快速下拖 100px 以上，10 次里至少 9 次触发掉落；缓慢下拖（<50px/s）或最大化切换导致的 ≤40px 位移，10 次里 0 次掉落。
- 日志不含窗口标题、文本内容；默认关闭；关闭时无磁盘写入。

### F2 拆分 `window.py` + 默认骨骼体验（P0，3 天）

**内容**
1. 把 `window.py` 拆成：`window.py`（窗口壳、拖拽、点击）、`motion_driver.py`（散步/原地驱动）、`interaction.py`（摸头、眼睛跟随、趴窗口接线）。保持对外信号与菜单回调不变。
2. 将「部件骨架（待机+行走）」「部件转身」从实验开关转为：资源齐全时默认开；任一资源缺失或加载失败自动回退预渲染片，并在日志里记一次原因。保留菜单里的「回退到预渲染」开关。
3. 为眼位等硬编码（D7）改成从 `rig.json` 读取，缺省用当前常量。

**验收标准**
- 全量测试通过，用例数不下降；拆分前后 `window.py` 单文件 ≤ 400 行。
- 删除 `part_rig/part_turn` 设置后首次启动，待机即为骨骼渲染；人为移走 `assets/rig25d` 后启动，不崩溃、自动回退，日志有 1 条原因。
- 眼位改读 `rig.json` 后，离屏渲染对比图与改前像素差 ≤ 0.5%。

### F3 设置面板与引导（P0，2 天）

**内容**
- 一个设置窗口（非模态、不抢焦点）：外观（大小）、行为（模式、眼睛跟随、摸头及灵敏度、趴窗口、自己走过去）、屏幕感知（三档开关、额度用量）、权限状态（辅助功能：已授权/未授权 + 一键打开系统设置）。
- 首次启动三步引导：说明她会做什么、说明默认关闭的权限、完成。
- 右键菜单保留常用开关，复杂项进设置面板。

**验收标准**
- 面板里每个开关与菜单状态实时一致（两处任一修改，另一处刷新）。
- 辅助功能未授权时，「精确到输入框」旁显示明确提示，不静默失败。
- 面板打开/关闭全程不改变前台应用的键盘焦点（真机在输入文字时打开面板验证）。

### F4 跨会话记忆（P1，4 天）

**设计**
- 本地存储（配置目录下 `memory.json`，0600 权限）：
  - **事实记忆**：用户称呼、偏好、反复出现的事（如「主人在写论文」）。
  - **近期记忆**：最近 N 次对话的摘要（每次对话结束或超过阈值时由模型生成，**限频：每天最多 5 次摘要调用**）。
  - **人格设定**：固定人设，不随记忆改变。
- 注入方式：系统提示里附「记忆摘要」，总长度上限 600 字，超出按时间淘汰最旧。
- 隐私：菜单「查看/清除记忆」；不记录屏幕截图内容，屏幕评论只保留一句话摘要且可关闭；密码、银行类内容不入库（沿用屏幕黑名单）。

**验收标准**
- 重启后，问「我刚才在聊什么」能引用上一次对话的要点（人工用 5 个案例验证，≥4 个正确）。
- 一天内摘要调用次数 ≤5（计数器单测 + 日志）。
- 「清除记忆」后 `memory.json` 内容为空，下一次对话不再引用旧内容。
- 记忆文件不含 API Key，权限为 0600。

### F5 主动开口 v2（P1，3 天）

**设计**
- 事件源（均为本地判断，不花额度）：切换到新软件、连续使用 N 分钟、回到电脑（空闲后恢复）、整点、天气变化、摸头 N 次后的「撒娇」台词。
- 一个统一的「开口调度器」：全局每小时最多 3 次主动台词（可配）、聊天框打开/流式回复/安静模式/全屏时不开口；与已有台词冷却合并，避免多路同时冒泡。
- 可选：把事件上下文交给模型生成一句话（走和屏幕视觉同一套限频/用量计数，默认关）。

**验收标准**
- 连续使用 2 小时的模拟时间轴测试：主动台词总数 ≤6，且不出现间隔 <5 分钟的两条。
- 聊天框打开、安静模式、流式回复期间主动台词数为 0（单测）。
- 关闭「主动开口」后，除用户触发（点击/摸头/掉落）外无任何台词。

### F6 情绪状态机与表情补全（P2，4 天）

**设计**
- 在现有状态（idle/think/sleep…）之上加一层「情绪」（平静/开心/困/惊讶/委屈），由事件驱动（摸头→开心，掉落→惊讶，长时间无人理→委屈，深夜→困），按时间衰减回平静。
- 素材：补「惊讶嘴型」「委屈」两个嘴型部件；瞳孔分层（解决 D7 与眼睛跟随幅度偏小的问题）。素材用接口按已定稿形象生成，逐张人工审。

**验收标准**
- 情绪切换有 0.3–0.6 秒过渡，无跳变（离屏逐帧检查）。
- 每种情绪离屏渲染一张图，Wiki 逐张确认形象一致（发饰、项链、服装不变形）。
- 情绪不改变既有的聊天/趴窗口行为（回归测试通过）。

### F7 完整侧身趴卧与更多趴姿（P2，5 天）

**设计**：补侧身趴卧、蜷缩睡的素材（接口生成 + 逐张审），趴窗口时随机选姿；掉落时从侧趴到站立的过渡走渐变。

**验收标准**：每种趴姿可进入/退出/睡着；窗口边缘移动时不穿帮；形象一致性人工确认；素材调用次数与花费记录在文档里。

### F8 语音（P3，4 天）

**设计**：先做 TTS（回复可选朗读），用户可关；语音与气泡同步；不做常驻麦克风监听（权限与隐私成本高），后续单独评估「按键说话」。

**验收标准**：开启后每条回复 ≤1.5 秒内开始出声（网络正常时）；关闭时无任何音频权限请求；朗读期间桌宠嘴型/气泡不卡顿（帧率不低于现状 90%）。

### F9 打包/发布（P3，3 天）

**设计**：脚本化打包 → 签名/公证 → 版本号 → 应用内「检查更新」（只提示，不自动替换）。解决 D9：固定签名身份，使辅助功能授权在升级后保留。

**验收标准**：全新 Mac 上从下载到运行 ≤5 分钟，无需终端；升级后辅助功能授权保留；包体积较现在不增加超过 20%。

### F10 换装/皮肤包（P3，5 天）

**设计**：把部件、眼位、锚点、台词前缀全部数据化到一个角色包目录，菜单可切换；不做在线商城。

**验收标准**：用一个换了发色的测试包，不改代码即可切换并完整运行（含摸头、趴窗口、掉落）。

## 附录 A 真机检查清单（本版交付后由 Wiki 或我方逐项确认）

1. 右键菜单：「眼睛看向鼠标」默认勾选；「模式」里只有「散步」「原地」；旧设置里是「看向鼠标」的会自动变成「原地」+ 眼睛跟随。
2. 鼠标从桌宠左右两侧、上下方划过：只有瞳孔移动，头、身体、朝向、位置都不变。
3. 在头顶来回摆 3 次以上：眯眼、耳朵压低、尾巴摇、轻微下沉，说一句带「喵」的话；20 秒内再摸只有动作没有台词；鼠标离开或停止约 1 秒后恢复。
4. 单向划过头顶、鼠标静止在头顶：不触发。
5. 摸头时：不抢键盘焦点；拖拽、单击、双击聊天仍正常；按着鼠标键时不触发摸头。
6. 趴在窗口上沿时摸头：保持趴姿，只有轻微反应。
7. 趴着时快速把窗口往下拖：她被甩起一点，下坠，耳朵和尾巴上飘，说带「呀」的话；落到新的窗口边缘上会重新趴；下面没有窗口则落到屏幕底部压扁回弹后站起。
8. 趴着时把窗口往上拖：她跟着走（原有行为）；缓慢下拖：跟着下移，不掉落。
9. 菜单「摸头」里可开关，灵敏度低/中/高；改完立即生效，重启后保留。
