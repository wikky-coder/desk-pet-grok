## 修复：陪你做事不触发 / 红温 KeyError / 坠落只剩眼睛残影
- **KeyError: 0**：`shake.AngerMachine` 在晕/不耐烦自己消退时会发 `("stage", 0, old)` 事件，`interaction._anger_tick` 用 `shake.LINE[0]` 取台词→KeyError，抛在 `_puppet_tick` 里，打断那一帧的后续逻辑（含 `_work_tick`、`_greet_tick`）。现在 stage 0 只复位表情不说话（随后的 calm 事件另说「摸头」台词）。`tests/test_workfix.py`。
- **前台软件名读不到**：Mac 上 `lsappinfo info -only name` 在 GUI 会话外/部分环境输出为空；改为先用 NSWorkspace（ctypes objc，不需要 PyObjC/权限，子线程带 autorelease pool）读 `frontmostApplication.localizedName`，失败再退回 lsappinfo。在用户 Mac 上用真实设置实测：读到的是真实前台应用。
- **经典渲染（rig_auto=false、没设 part_rig）下不生效**：双手拿道具的躯干只在部件骨架里画。现在有道具时（`_work_mode`/`_work_t`）强制用骨架的站姿帧（`_extra_rig`），经典帧 ↔ 骨架帧走原有的短交叉淡入；`set_work` 时加载骨架。
- **诊断**：菜单「陪你做事」下面一行灰字 + 设置面板该项备注，显示「前台软件：X → 翻书/敲键盘/小终端/画板/不出道具；现在不出：趴着/生气/安静模式…；稳定 3 秒后出现」。
- 其他可能的抑制因素（符合设计）：趴着、扒边、生气、安静模式、被拖动、窗口隐藏时不出道具；同一软件稳定 3 秒、两次切换间隔 ≥25 秒。
- **坠落只剩眼睛的残影**：根因在 `partrig.paint`：整个人物被外层淡出（趴下↔站起的交接 `stand = 1-2·loaf`，以及赌气/扒边的交叉淡入）时，情绪脸层/开心脸层用 `setOpacity(fa)`/`setOpacity(1.0)` 画，没有乘外层不透明度，于是身体已经淡到几乎透明，脸层（眼睛+脸颊）仍是满不透明漂在上面。修为：进入 paint 时记下 `op0=p.opacity()`，所有脸层按 `op0*fa` 绘制并恢复到 `op0`（含新躯干层）。图 `_gen25d/rounds/fallfix/`（before_sheet / after_sheet / zoom_before_after_24_28）；测试 `tests/test_fallfix.py`（修复前 15 项失败）。

## 修复：甩她红温后摸头没反应 / 生气后台词不变
- **摸头**：红温阶段必须连续摸 1.2 s（赌气 2.5 s）且中断 1 s 就清零，而她的头部热区在小窗口（123×160）里只有约 69×56 px，光标稍一出区检测就掉，用户感觉「摸了没反应」，期间也没有任何反馈。改为：生气时头部热区放大（宽 +40%、高 +50%）并用宽松的摸头规则（同趴姿，任意方向来回都算）；逐级安抚：每摸约 0.9 s 降一级（赌气转回来→红温→鼓脸→平静），晕/不耐烦 0.4 s 直接消；中断 2 s 内进度保留；每一级有一句「还没原谅」的台词（anger_soothe），最后平静时出现开心脸 + 爱心 + 「哄好了」台词（shake_calm，12 句）。

## fallfix2：掉下来「只剩眼睛的残影」根因 + 趴姿切换频率
- **根因**：用真实路径（PetWindow + LoungeDriver 边缘掉落，经典渲染，lounge_variants/mood/look_at_mouse/tail_boost）逐帧离屏渲染，并模拟窗口遮罩（只保留 alpha≥50% 的像素）后发现：趴姿→站立交接时「站立图 opacity=1-2·loaf」与「趴姿图 opacity=smooth((loaf-.25)/.6)」在 loaf≈0.5~0.6 同时很低（覆盖度只有 ~20%），整只猫几乎消失，窗口遮罩只留下 alpha 较高的零星部位（眼睛、发饰、一圈轮廓）→ 就是用户看到的「只有眼睛的残影」（修复前第 7、8 帧，见 `zoom_before_after_6_9.png`）。另外多层半透明叠加（头发/耳朵/脸、趴姿底图+眼睛叠层各自以 a 绘制）会让头和眼睛比身体更不透明，加重这种效果。
- **修复**：①交接曲线改成「站立保持不透明，趴姿渐入到接近满再让站立在其下淡出」，合成覆盖度 `1-(1-s)(1-a)` 全程 >0.93（反向同理）；②站立 rig 与趴姿图（底图+眼睛/哈欠叠层）在 opacity<1 时先整体合成到离屏再按组淡入淡出，不再逐层叠加。
- **验证**：`scripts/render_fall2.py <tag> [variant] [sleep]`（MASKED=1 模拟遮罩，QT_SCALE_FACTOR=2 模拟 Retina）；图在 `_gen25d/rounds/fallfix2/`（`masked_*` 修复前、`masked_after_*` 修复后，`*_0_11.png` 为前 12 帧拼图，`zoom_before_after_6_9.png` 同一帧前后放大）。`tests/test_fallfix2.py`：5 种 变体/睡眠组合下，整段坠落任意帧的不透明（≥50% alpha）像素数都 >0.6×趴/站姿的像素数（旧代码 5/5 失败，新代码通过）；`test_loungeart.py` 增加覆盖度断言。
- **趴姿切换间隔**：由 90~240 s 改为每次换姿势后重新在 [40,120] s 内均匀随机（设置项 `lounge_variant_interval: [min, max]` 秒，范围夹在 10~900，max<min 取 min，坏值回默认）；仅在 空闲（未摸头、未打哈欠、未犯困、已完全趴下）时切换，睡着阶段仍保持蜷成一团；到点但忙则等空闲后立刻切。测试见 `test_lounge_variants.py`（均匀分布、每次重抽、设置夹取、忙时保持）。
